# 4단계: 파일 주고 받기

## 목적

- 연결된 상대에게 파일 하나를 보내고, 상대가 받아 저장할 수 있게 한다.
- 정말 파일을 주고 받는 데까지만 한다.

## 범위

| 하는 것 | 하지 않는 것 |
|---|---|
| 연결된 상대에게 파일 하나 보내기 | 큰 파일 나눠 보내기 |
| 받은 파일 목록에서 [저장]으로 다운로드 (이름·내용 그대로) | 성공·실패 기록 DB 저장 |
| 최대 크기보다 큰 파일은 보내지 않고 화면에 알림 | 진행률, 이어받기 |
| 보냄·받음·실패를 화면 로그에 남김 | 여러 파일 한 번에, 받기 수락·거절 |

## 최대 크기

- 브라우저가 DataChannel 메시지 하나로 보낼 수 있는 크기까지만 보낸다.
- 값은 연결된 뒤 `pc.sctp.maxMessageSize`로 읽는다. 양쪽 SDP의 `a=max-message-size` 중 작은 값이다.
- Chrome ↔ Chrome: 256 KB (262,144 B). 화면에 "파일 최대 256 KB"로 표시한다.
- 이보다 크면 보내지 않고 "보내기 실패: 파일이 너무 큼 (…, 최대 …)"을 보여준다.

## 방식

DataChannel은 연결 때 연 것(`punch`) 하나를 그대로 쓴다.

```
보내는 쪽                                   받는 쪽
문자열 {"type":"file", name, size, mime} →  파일 정보 저장, 내용 기다림
바이너리 (파일 내용 전체, 메시지 1개)    →  크기 확인 → 받은 파일 목록에 추가
```

- 문자열 메시지는 JSON이다 (`ping`, `pong`, `file`). 바이너리 메시지는 파일 내용이다.
- 빈 파일(0 B)은 내용 메시지를 보내지 않는다. 받는 쪽은 `size: 0`이면 바로 끝낸다.
- 받은 파일 정보는 검사한다: 이름 1~255자, 크기 0 이상 정수, 형식 100자 이하. 내용 크기가 `size`와 다르면 버린다.
- 받은 내용은 형식을 `application/octet-stream`으로 고정한다. 상대가 html 등으로 속여 보내도 이 페이지에서 실행되지 않고 다운로드만 된다.

## 코드

| 파일 | 바뀐 것 |
|---|---|
| `lib/connection.ts` | 인터페이스에 `sendFile(file)`, `maxFileSize()` 추가. 이벤트에 `file` 추가 |
| `lib/rtc.ts` | `RtcLink.sendFile`, `maxFileSize`, 받기 처리(`onBinary`, `receiveFile`), 파일 정보 검사 |
| `lib/punch.ts`, `lib/local.ts` | `sendFile`, `maxFileSize`를 `RtcLink`에 넘김 (두 방식 같음) |
| `lib/peer-manager.ts` | `sendFile(peerId, file)`, 받은 파일 목록(`snapshot.files`), 세션의 `maxFileSize`·`fileNote` |
| `lib/format.ts` | 바이트 표시 (`256 KB`) |
| `components/PeerList.tsx` | 연결되면 [핑] 옆에 [파일 보내기], 최대 크기와 마지막 보내기 결과 표시 |
| `components/ReceivedFiles.tsx` | 받은 파일 목록과 [저장] |

## 완료 기준

- 연결된 두 기기 사이에 파일을 보내면 받는 쪽에서 같은 이름·같은 내용으로 저장된다.
- 최대 크기보다 큰 파일은 보내지 않고 화면에 알린다.

## 진행 상황

| 항목 | 상태 |
|---|---|
| 구현 | 완료 |
| 로컬 테스트 (같은 Chrome 두 탭, `host ↔ host`) | 성공, 아래 표 |
| 배포 주소 테스트 | 대기 (push 전) |
| 다른 네트워크 테스트 (PC ↔ 휴대폰 모바일 데이터) | 대기 |

로컬 테스트 결과 (받은 파일을 저장해 원본과 MD5 비교):

| 파일 | 결과 |
|---|---|
| 100 KB | 보냄 → 받음, 이름·내용 일치 |
| 256 KB (최대와 같음) | 보냄 → 받음, 이름·내용 일치 |
| 256 KB + 1 B (최대 초과) | 보내지 않음, "파일이 너무 큼 (262,145 B, 최대 262,144 B)" |
| 빈 파일 (0 B) | 보냄 → 받음, 이름·내용 일치 |

- 페이지 오류 없음. 파일을 주고받은 뒤에도 연결 유지.
